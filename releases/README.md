# ICUdata releases

One folder per ICUdata release, holding the artifacts that describe that release.

## Layout

```
releases/
├── README.md                     # this page
└── v<MAJOR>.<MINOR>.<PATCH>-<YYYY-MM-DD>/
    ├── release-notes.md          # what is new, in plain language (from v0.3.0)
    ├── changelog.md              # what changed vs. the previous release
    ├── concept_taxonomy.yaml     # every concept, grouped by clinical question (from v0.3.0)
    ├── concept_taxonomy.md       # the same, as a page to browse on GitHub (from v0.3.0)
    ├── dictionary.csv            # full concept dictionary as of this release
    └── dictionary/               # the same dictionary, one CSV per table
```

Each release folder is named with its version and release date, e.g.
`v0.2.0-2026-06-29/`.

## What's in a release folder

- **`release-notes.md`** — the changes since the previous release in plain
  language, sorted into large, medium and small changes, in Dutch and English.
  From v0.3.0 on.
- **`changelog.md`** — auto-generated by diffing this release against the
  previous one. Sections (only those with content appear) include *Breaking
  Changes*, *Hospitals Added*, *Tables Added*, *Schema Changes*, *Concept
  Changes* and *Parameter Remappings*. From v0.3.0 on it is generated
  completely by the build and starts with a link to the release notes.
- **`concept_taxonomy.yaml`** and **`concept_taxonomy.md`** — every concept of
  the release, grouped by the clinical question it answers (category,
  subcategory, topic), as a file and as a page to browse on GitHub. From v0.3.0
  on; v0.2.0 has the older list `common_concepts.yaml`.
- **`dictionary.csv`** — the full concept dictionary as of this release: every
  concept with its statistics (row counts, patient counts, per-hospital patient
  coverage, units).
- **`dictionary/`** — the same dictionary as one CSV per OMOP table
  (`measurement.csv`, `drug_exposure.csv`, …); v0.2.0 also has a `README.md`
  index. The
  full `dictionary.csv` exceeds GitHub's table-render limit; the per-table
  files are small enough to display inline. From v0.3.0 on, the columns differ
  per table, and `<table>_values.csv` files list the coded answers per concept.

Numbers of patients below 10 are hidden in both dictionary files. A concept
with fewer than 10 patients shows `<10` and has no record count and no coverage
percentages; in other rows, a hospital's coverage percentage that stands for
fewer than 10 patients is left blank. This applies to every release from
v0.3.0 on, and was applied to the published v0.2.0 dictionary afterwards.

## Versioning

Release folders use `v<MAJOR>.<MINOR>.<PATCH>`. The largest change in a release
determines the bump:

| Change in the release | Bump |
|-----------------------|------|
| Hospital, table, column, concept or coded answer removed (a hospital with no rows left in a table counts as removed from it); column type changed; parameter or coded answer remapped to another concept | minor (`0.x.0`) |
| Any other change, additions included (hospital, table, column or concept added, row-count change) | patch (`0.0.x`) |
| Nothing | no change |

A minor bump means a query written for the previous release may fail or return
rows that mean something else. This rule applies from v0.3.0 on; before, an
added hospital or table also raised the minor number.
